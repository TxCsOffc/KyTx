# FC27 Metal — хендовер конца сессии 2026-10-25 (вечер, Claude)

Читать после [stencil follow-up](porting-followup-fc27-metal-2026-10-25-stencil.md) (там же раздел «Третья причина…»). Всё **не закоммичено** (по правилу проекта), FEX + прямой RDNA→MSL, Vulkan только как визуальный эталон. Эмулятор, gpudebug и скрипты остановлены; игры/сессий не осталось.

## Цель и принцип работы
Правильный матч FC27 ≥ 30 FPS на Metal. Пользователь: в **меню** (фон «Classic Match», «Training Hub», главное меню) тоже играют настоящие игроки с мячом — те же скиннинг/G-buffer/освещение/TAA, что и в матче, поэтому **чинить по меню**, матч после этого почти сам. В живом матче сейчас рисуются только HUD/радар, поле и игроки чёрные.

## Что исправлено в этой сессии (в сборке; отключатели в скобках)
1. **HTILE fast clear глубины** (`metalRenderer.mm`: `RegisterHtile`/`NoteHtileWrite`/`TakePendingDepthClear`; `KYTY_NO_HTILE_CLEAR=1`). Игра чистит depth не clear-draw'ом, а compute'ом по HTILE (как `TryConsumeComputeMetaClear` в Vulkan). Эффект: у главного меню появился настоящий фон; G-buffer меню Kick Off с геометрией.
2. **Compute-картинки: «последний писатель выигрывает»** (`LastGpuWriterTexture`, `NewestRenderTargetFor`; `KYTY_NO_LAST_WRITER=1`). Раньше sampled-картинка compute по адресу брала устаревший объект из реестра `GetComputeWrittenImageForAddress`, а не свежий render target. Последняя найденная причина (**проверка не завершена**): сцена лежит в RT с **цепочкой 10 mip-уровней** (`RtLayout … addr=0x8243f40000 1600x904 mips=10`), а RT-путь их отбрасывал (`mipmapLevelCount != 1`) — разрешено, собрано, но результат на фоне Classic Match не подтверждён (прогон упал, см. «Падения»).
3. **Depth как текстура у draw'ов** (`GraphicsImageFor`: depth-писатель того же размера → сам Metal depth). Раньше velocity/TAA-проход читал `GuestTex` — копию почти пустой памяти → мусорная скорость.
4. **CMASK-fill не рвёт проход** (`MetalContext::QueueBlitFill`, `MarkCmaskTouched`; `KYTY_CMASK_SPLIT=1` — старое). Xcode: 245 UI-энкодеров, 8,47 из 11 GiB/кадр. FPS-эффект не замерен.
5. Заголовок окна macOS: `KyTx | <игра> (<TITLE_ID>) | frame: N, fps: N` (`window.cpp`).
6. Сервис: F9 / `touch /tmp/kytx_capture_now` — GPU-трасса; `KYTY_AUTO_INPUT` понимает `up/down/left/right/enter`; `KYTY_AUTO_INPUT_FILE=/tmp/kytx_input` (команды `down:8 wait:40 j:8`, между нажатиями в меню ≥ ~30 флипов).

## Диагностические переключатели (все opt-in, в `metalRenderer.mm` кроме указанных)
`KYTY_LOG_DEPTH` (гистограмма depth-состояния), `KYTY_LOG_CS_IMAGES=<hash cs>` ([CsImage]/[CsImageT#]/[CsImageLW] — как разрешены картинки, T# dwords, RT/last-writer), `KYTY_LOG_CS_ADDR=<addr>`, `KYTY_LOG_CS_WRITES=<lo>,<hi>` (какие compute пишут в диапазон), `KYTY_LOG_VBUF=<VS hash | 1 = скиннинг-VS>` (V#, позиции, instance-записи, строки пула матриц), `KYTY_LOG_INFLIGHT` (отставание GPU, в `metalContext.mm`), `KYTY_LOG_RT_LAYOUT`, `KYTY_MSL_DUMP_DIR=<dir>` (MSL каждого шейдера), `KYTY_LDS_SYNC=1` (**эксперимент**, `MslEmitter.cpp`: barrier вокруг LDS; на мусор Classic Match **не повлиял**, оставлено выключенным).

## Открытые проблемы (по приоритету)
1. **Классическое меню «Classic Match»: блочный мусор вместо 3D-фона** (верхние ~40 %: белые/чёрные/оранжево-зелёные прямоугольники 64 px). Вход тонмаппинга (CS `fe68b32aafc98c9a`, затем композит CS `7615e9bfcae5c55a`) читал устаревшую копию памяти (`tex313/394` R32Uint, детайл в начале кадра). Исправления 2 выше должны это закрыть — **перепроверить первым делом**. Заметка: адрес T# (`0x8243f40000`) отличался от RT-адреса (`0x8243f30000`) на 64 КБ; `0x8243f40000` как RT с 10 mip появляется с flip ~5547.
2. **Матч: поле/игроки чёрные.** G-buffer (`cb4/re5`, 186 draw'ов) содержит стадион и «лучи-осколки» из одной точки (схлопнутые вершины игроков); вершинные потоки здоровы (позиции float3 без NaN/нулей: b3; b1 = UV+id). VS `0xa99d37957916f7fa` берёт матрицы из пула `0x817d000000` (1,6 млн float4, 25,6 МБ) по индексам из записей b4; в логе `pool[274]` = нули, `pool[0]` = NaN. Пул пишут compute `0x0cf7218b746c22e4` (копирует диапазоны из **CPU-staging 512 КБ** `0x8192…/0x8195…`, кольцо из 3 адресов; список диапазонов b0 — 80–112 байт) и `0xb4e7772f20bc59da` (7456 строк). Снапшот при кодировании есть только для буферов ≤ 16 КБ в `0x8190…–0x81a0…` — staging 512 КБ не снапшотится; GPU отстаёт всего на 2–4 command buffer'а (мало), но гонку CPU/GPU на staging не исключает. Прецедент из `kytyps5-ufc5/ufc5/ledger.md` (UFC 5, чёрный раунд): неинициализированная 1×1 текстура авто-экспозиции (1e-19) умножала сцену на 1e-16 → NaN в temporal-upscaler → чёрное. Проверить у FC27: 1×1/буфер экспозиции, значения в `GuestMemoryUMA`-пуле на входе тонмаппинга.
3. **Чёрный «шум» 8×1–2 px** (штрихи) на сцене Training Hub/после TAA — источник не найден; LDS-барьеры не помогли в Classic Match (на Training Hub не проверялось). Кандидаты: wave64-CS (`30d055428c21287c`, 12 тыс. строк, `kyty_lds[256]` без барьеров) на 32-lane SIMD, мусорная скорость (исправлено п.3, не перепроверено на матче).
4. **Случайные падения гостя**: `Unhandled host exception … Job2/Job4/Job8`, адреса вида `0xac933a…`, `0x18`, `0xffff…abf0`, pc в JIT-коде (`runtimeLinker.cpp:754`) — в ~1 из 4–5 длинных прогонов, иногда после нажатий в меню. Причина не установлена (HLE/FEX JIT/порча памяти). Нужен pc→гостевая функция.
5. Превью-картинки меню (баннеры, иконки) — цветной шум; текстуры декодируются неверно (не изучено).
6. EA-интро, `KYTY_EOP_CLOCK_FREEZE`-обход, FPS в матче (меню 26–30 fps).

## Как воспроизвести сцену для отладки
- `open -n .porting/work/KyTxMetal.app` (читает `.porting/work/extra_env.sh`: `RUN_TAG=…`, диагностические флаги, `KYTY_AUTO_INPUT=…j каждые 350 флипов до 2900`, `KYTY_AUTO_INPUT_FILE`). **Перед запуском проверить `pgrep -fl kyty_emulator`**; убивать только `.porting/tools/killmine.sh` (по `RUN_TAG`).
- `.porting/work/drive.sh <лог>` — сценарий «Press Any Button → Play Offline → Down×5 → Enter → OK». **Ловушка:** старые экземпляры drive.sh продолжают слать нажатия в новые запуски (из-за этого меню проходилось по-разному) — перед запуском `pkill -f drive.sh`. Экран, куда приземляется сценарий, зависит от состояния сети/меню (Classic Match, Training Hub или матч).
- Скриншот окна: `.porting/work/shot.sh <png> [ширина]`; GPU-трасса: `touch /tmp/kytx_capture_now` (в запуске `MTL_CAPTURE_ENABLED=1`, `KYTY_GPU_CAPTURE_DIR`). **Трасса меню = 33–141 ГБ и растёт с длиной сеанса** (держит все созданные ресурсы); загрузка в gpudebug 10–15 мин. Остались: `captures/fc27-20261025/htile/frame9600.gputrace` (матч, 96 ГБ) — удалить после разбора.
- gpudebug: `-t <trace> --timeout 0 -c status` создаёт сессию (потом `--terminate <id>`; **проверять `gpudebug -l`**, сессии остаются жить); ресурсы: `go /resources/textures` + `fetch texN --out f.png`, `info texN --all`; `find <имя>` ищет по API-вызовам; у compute-узла `buf[0]/tex[0]` повторяются — адресовать по порядку нельзя. Скрипты: `.porting/work/inv.py <session> <tag>` (контактный лист проходов), `gd.py`.

## Среда
- Computer use после форка сессии: `~/.claude/computer-use.lock` залипает (перенесён в `.bak-20261025`), права Accessibility/Screen Recording надо перевыдать и перезапустить Claude (память: `reference_computer-use-lock.md`). Xcode только click-tier; в Xcode Dependencies для 300+ draw'ов читаем плохо, полезнее Summary → Insights (Bandwidth/API Usage).
- Удалено по просьбе пользователя: `kytyps5-ufc5/_Build` (78 ГБ), `kytyps5-ufc5/runs` (25 ГБ), старые трассы и `validation-20261023/24`; свободно ~658 ГБ.

## Почему сеанс шёл долго (честно)
Каждая проверка гипотезы = пересборка + запуск + ~8–10 мин доигрывания меню по скрипту; GPU-трасса меню 100+ ГБ грузится в gpudebug 10–15 мин, а я часто держал их по одной на гипотезу; плюс «залипшие» фоновые скрипты и блокировка computer use съели несколько часов. Разумнее: **один длинный запуск с набором логов**, заранее прописанный сценарий и не открывать новые трассы без нужды.
