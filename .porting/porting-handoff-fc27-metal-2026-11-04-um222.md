## 2. Ключевые изменения в коде

### [src/graphics/host_gpu/metal/metalRenderer.mm](file:///Users/tx/Developer/KyTx/src/graphics/host_gpu/metal/metalRenderer.mm)

- **`LayeredSlicesFor`:**
  ```cpp
  static uint32_t LayeredSlicesFor(const ShaderTextureResource& tex, uint64_t addr, uint32_t w, uint32_t h, bool cube, bool array) {
      const uint32_t base_slice = (cube || array) ? tex.BaseArray5() : 0u;
      const uint32_t depth      = (cube || array) ? static_cast<uint32_t>(tex.Depth()) + 1u : 1u;
      uint32_t slices = cube ? std::max<uint32_t>(6u, std::max<uint32_t>(depth, base_slice + 6u))
                             : std::max<uint32_t>(std::max<uint32_t>(depth, base_slice + 1u), (w == 256 && h == 32 ? 20u : 1u));
      static std::unordered_map<uint64_t, uint32_t> s_max_declared_slices;
      static std::mutex s_max_slices_mutex;
      std::lock_guard<std::mutex> lk(s_max_slices_mutex);
      uint32_t& max_s = s_max_declared_slices[addr];
      max_s = std::max(max_s, slices);
      return max_s;
  }
  ```
- **`LayeredImageFor` и `PrepareLayeredImages`:**
  - `const bool cube = img.cube || tex.Type() == Prospero::ImageType::kCube;`
  - `const bool array = img.dimension == Dim::Dim2DArray;`
  - `const bool layered = cube || array;`
  - Текстуры, не являющиеся кубами или массивами, игнорируются, не забивая кэш и не подменяя обычные 2D compute буферы/LUT.

## 8. GPU-закодированные BC-текстуры: форма, герб, логотип (Claude, 2026-11-04 15:55, um235–um240)

**Нашёл.** Вторая (главная) причина шума формы. Игра сама сжимает в BC на GPU форму, гербы и значки: ядро пишет BC-блоки в тайловый storage-образ RG32Uint (8-байтные блоки) / RGBA32Uint (16-байтные) по адресу текстуры, а draw читает его как BC через сотни флипов. Трасса um236 (тренировочное поле, Англия, flip 2393): у draw'ов игрока n=23/26 входы `tile=9` 2048² BC3 sRGB, 1024² BC5/BC1/BC1 sRGB, 128² BC4 с писателями `512x512 f123` / `256x256 f113` на flip≈1577; `lv=10/10` (mip-цепочка полная, гипотеза «нет мипов» отпала). Без UMA storage-образ Metal — отдельная текстура, в гостевую память записи не попадают; `AliasConvert` доверяет писателю 2 флипа, дальше `GuestTexture` декодирует старые гостевые байты → шум. Доказательство: um237 с `UMA=1` (storage = вид гостевой памяти) — майка Реала гладкая, герб на экране студии верный (сам UMA-режим в остальном сломан: чёрный экран до t≈160, блоки, белые кадры).

**Исправил (по умолчанию включено).** `BcWriteback` (`metalRenderer.mm`, перед `DispatchCompute`): после dispatch'а storage-образы RG32Uint/RGBA32Uint, тайловые, одноуровневые (T# base=last=0), не render target, экспортируются в гостевую память в тайловой раскладке (`EncodeTileExport` в буфер `GetBufferForGuestRange`, как оставило бы железо); BC-копия видит новые байты через `GuestTexStillCurrent` и декодируется заново. Только мьютекс кэша буферов, менеджер гостевой памяти не трогается. `KYTY_NO_BC_WRITEBACK=1` — выключить, `KYTY_LOG_BC_WRITEBACK=1` — лог (каждый адрес один раз, до 400; плюс пропущенные кандидаты).
