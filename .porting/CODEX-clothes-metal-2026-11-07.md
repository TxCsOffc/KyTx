## ROOT CAUSE FOUND AND FIXED (Claude, run mc19): MSL dispatcher had no jump-table (IndirectBranch) support

The mask layering kernel (guest 1e542024957cf5df, native 1e482805ca472a89) selects its blend mode through an `s_setpc_b64` jump table. CFG (`TerminatorKind::IndirectBranch`, `ResolveSetpcJumpTable`) and the SPIR-V dispatcher handle it; the MSL emitter's structured path rejects it (falls back to the dispatcher) and the dispatcher's `default:` printed `return;` for every terminator that is not Branch/ConditionalBranch. In the dumped MSL block 9 ended with `return;` and blocks 10-31 (the only image write) were unreachable, so the kernel never wrote anything: cutout layers had no effect, street masks stayed white (255), the culling kernel (08219d1d43a82464) saw white masks and culled nothing, and skin showed through street clothes. In mc3-mc18 every run had 0 degenerate triangles on street frames.

Fix (uncommitted): `MslEmitter.cpp`, dispatcher switch over `term.kind`: new `case IndirectBranch` emits `if (selector == value) { phi copies; pc = BlockIndex(target); } ... else pc = 0xffffffff` using `indirect_selector_values/targets` (or `indirect_target_pcs/targets`), the same data the SPIR-V dispatcher uses; an unknown selector leaves the shader (default: return) and a block without selector data still returns.

Result mc19 (one run, same build otherwise): body masks bound by the body shader now include 39.8 (15.6% white / 84.4% black) and 29.0 (10.9% / 88.1%), identical to the Vulkan reference masks (means 39.8, 29.0), plus 65.8 and 118.7; kit masks unchanged (130.1, 122.8). Legs index lists: 15256 / 17134 / 18603 of 20172 degenerate (reference 17071), torso 9817-11013 of 32686. Frames 1900 and 2400 (street, jeans and shirt): no skin patches. No GPU hang/watchdog/command-buffer-error lines, median FPS 29.5 (mc3: 28.5). Only 1 of 914 shaders in the run used the dispatcher (structured=0), i.e. this kernel. ### Vulkan white screen: tile classification differs (static analysis of logs + MSL, no runs)

Compared the lighting phase of a Vulkan trace (vk8, flip 1688, real indirect args) with the Metal frame (mc21 frame 1800). The kernel chain is identical (bb1415e0 x9 copy -> df0a2346 x8 -> 3b4f635e -> 0e838ae6 -> ... lighting kernels in families of six). What differs is the indirect group count per class:

| family | Metal (classes 0..5) | Vulkan |
|---|---|---|
| 1691cb86 / 45ff7d9d / 661481cd / 77b2d6ce / a4c06b45 / 28e424b7 | 768 / 640 / 192 / 0 / 0 / 0 | 1984 / 0 / 0 / 0 / 0 / 0 |
| daa8c31f / 79babc35 / b4459214 / ... | 832 / 512 / 192 / 0 .. | 1984 / 0 / 0 .. |
| 15ef8445 / 2168dc94 / ff98d6cd / ... | 448 / 512 / 640 / 0 .. | 2048 / 0 / 0 .. |
| 0e838ae6 | 2944 | 8448-12608 |

So in Vulkan every tile lands in class 0 and the other classes get nothing. Class-0 kernels then shade tiles that need another model, which gives the tile-aligned NaN blocks. Metal is correct here.

Mechanism (MSL of df0a2346 = Metal cs 3adccdf8dca1fa06, `.metal` in mc19-msl): per 8x8 thread = one pixel/tile entry; reads params (buffer0: width, height, increment, bit index, shift), a per-entry 32-bit mask (buffer1, tests bit `buffer0[3] & 31`), an 8-byte table record (buffer2: class bits in the TOP NIBBLE of both dwords: v45 = table.y >> 28, v47 = table.x >> 28; list index 0..7 from those), then `atomic_fetch_add` on the per-class counter (buffer3, stride 16 B: these ARE the indirect args records) and writes the packed tile coordinate (x << 16 | y) into the per-class list (buffer4, 16320 B). bb1415e0 only copies a 128-byte template into the counter blocks first. So Vulkan reads a table/mask whose class nibbles are zero (or an atomic that does not accumulate per class), i.e. the producer of buffer1/buffer2 (earlier kernels, indirect, some with 0 groups in both backends) differs.

### Claude, 2026-11-08: ROOT CAUSE of the missing fill light found and fixed (RECTLIST winding), UNCOMMITTED
**Cause.** The FC 27 light-cell pass draws every light as a guest RECTLIST rectangle (instanced indirect draw, `cb26/re0/draw0` in the traces, 4-vertex strips in Metal). Its pixel shader reads `front_facing`: list-A bit (`atomic_fetch_or` into buffers[4]) for front-facing, list-B bit (buffers[5]) for back-facing rectangles. The Metal rect-list vertex wrapper built every strip as (a, b, c, r) which came out front-facing for all rectangles, so list B stayed empty, the table entries written by the culling kernel (`1af7217f`, grid 30x17) had a zero high nibble in every cell, the classifier df0a2346 never produced classes 4-7 and the lighting kernels of those classes (the ones that apply the second light list) got 0 groups. Result: the lit scene lost its fill light (near-black shadows). Clean Vulkan frames (tessellated rect-list emulation) have the B list populated.
**Fix (uncommitted).** `src/graphics/shader/recompiler/backend/msl/MslEmitter.cpp`: in the non-indexed rect wrapper the two non-corner vertices are swapped (strip a, c, b, r) so the winding is reversed; `KYTY_RECT_LEGACY_FACING=1` restores the old order. `src/graphics/host_gpu/metal/metalShader.mm`: MSL disk cache schema bumped `msl-s2` -> `msl-s3` (translator output changed). The earlier experiment switch `KYTY_RECT_FLIP_FACING` no longer exists.
**Evidence.** PassTrace class counts (8x8x1 indirect passes, 6 per block, positions = classes 0,1,2,4,5,6): before the fix every Metal trace had classes 4-6 at 0 (mc25, mc33 `[2368,25472,4800,0,0,0]`, frame2538 `[12288,13632,6656,0,0,0]`); with the fix mc37 `[11968,0,0,6976,8704,4736]` (Vulkan clean frame `[0,0,0,3584,20416,4608]`) and mc40 has class 5/6 groups in block 0 plus class 4 groups in other blocks.
